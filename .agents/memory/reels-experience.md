---
name: Reels experience
description: Approved Reels visual direction and user-requested posting, sharing, saving, and commenting behavior.
---

The user liked the first Reels picture preview and wants that visual direction retained.

**Why:** The user said, “I like the way you edit it.”

**How to apply:** Use the approved picture as the visual reference rather than starting a different design without asking.

Reels are videos. Posting must offer recording with the camera or selecting an existing video, then publishing after upload and processing finish. Sharing must include people the user already chats with. Saving must make the video accessible again to that user.

**Why:** The user described recording or selecting videos, posting immediately, sharing with chat partners, and finding saved videos later.

**How to apply:** Do not substitute static pictures for Reels or a nonfunctional share/save icon for the requested actions. Do not imply publishing occurs before the video is ready.

Use record-and-post, not live broadcasting.

**Why:** When asked to distinguish recording from broadcasting, the user selected “Record and post.”

**How to apply:** Offer recording or choosing a video, previewing it, and posting it. Do not add real-time streaming as part of this scope.

Comments must open low down without covering the video.

**Why:** The user explicitly requested that “the comment will not cover the video.”

**How to apply:** Reserve space below the visible video for the comment panel and input instead of placing an opaque sheet over the video.

Opening Reels must show a full-screen vertical feed with no main branding header, bottom navigation tabs, or in-app notification popups over the video. Users swipe up and down to watch more public member Reels; the feed is not limited to mutual matches.

**Why:** The user requested full-screen viewing, no notifications showing there, and continuous up/down scrolling through anybody's Reels.

**How to apply:** Treat the full-screen viewer as a separate viewing state, paginate available public videos, and provide a way back to the app. Do not promise to suppress notifications generated by the phone's operating system.

Reels must play automatically, with controls to pause and mute or unmute.

**Why:** The user explicitly said, “Reels play automatically. The person can stop or mute.”

**How to apply:** Start the visible video muted and inline to meet mobile browser autoplay rules, pause off-screen videos, and show a clear play action if the browser blocks autoplay. Do not replace the requested playback behavior with static previews.
